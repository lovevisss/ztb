## 当前切片边界

- CAS 登录现已接入；组织数据可由管理员导入校方 JSON 快照并配置岗位角色映射，正式接口仍待校方资料。原本地登录暂保留作过渡。申请提交要求用户已有部门关联。
- 默认 10 万元规则由数据库迁移创建；采购管理人员和系统管理员可以安排全校或指定部门的新规则。当前角色需要由数据库或后续角色管理切片分配。
- 提交申请时会匹配审批模板并生成顺序审批任务；缺少匹配人员时阻止提交。退回后重提新建审批轮次，旧审批意见保留。默认流程均含部门负责人和采购管理部门两级，正式制度落地前须由采购管理部门确认和配置。
- 第 4 切片之前已提交的项目不会自动生成审批任务；真实数据迁移时需逐项核对并补建流程实例。
- 统一招标已使用独立表单，需求书和预算依据是提交必需材料，附件保存在私有磁盘并经申请人权限校验后下载。第 3 切片之前创建的统一招标记录未自动补齐历史材料，应在真实数据迁移时核查。
- 审批工作台和流程配置已使用 Element Plus；旧申请页面仍使用起始模板组件和 Tailwind，后续逐步统一。
- 经费列支、组织形式、采购方式和归口部门目前为文本输入；正式字典由学校提供后改为受控选项。
- 历史查询展示已提交项目；普通教职工可查本部门，采购管理人员可查全校，归口人员可查本部门归口项目。复制时仅复用可编辑业务字段，附件、审批记录与分类结果需在新申请中重新提交或生成。
- 审批通过后可由申请人、指定执行人或采购管理人员登记执行结果。支持分次保存、实际金额与申请预算不同、五类私有执行附件；指定执行人可跨部门查看和登记。
- 归档要求执行已完成且必需材料的私有文件仍存在。系统管理员可分别配置自行采购和统一招标的五类材料是否必需，默认合同、结果公告、验收材料及发票均为必需的示例规则；正式清单到位后应调整。归档保存规则与附件 ID 快照，保留申请、审批和执行记录，所有现有修改入口在归档状态下拒绝写入。
- 采购统计复用历史项目的授权范围，支持年度、部门、归口、采购方式、组织形式、经费、采购类型、项目状态、执行与归档状态筛选。数字卡片、年度或月度趋势、部门排行、方式与类型分布和明细共享同一筛选结果；Excel 文件也使用同一查询。实际采购总额只计完成执行的金额，平均审批耗时以提交时间至最后一次通过事件计算。当前统计与导出一次加载筛选结果，数据量增长后需改为数据库聚合与流式导出。
- 东方学院 CAS 协议包已接入，并按正式域名配置回调、退出返回与 SLO 地址；账号映射、在职拒绝及本地会话保护已实现。详见 [CAS 对接说明](cas-integration.md)。A51 目前通过模拟 CAS 的集成测试，真实学校登录需平台登记地址和人员数据。A52–A53 的本地组织导入与角色映射已通过集成用例，正式组织接口待协议适配与联调；A54–A56 的门户待办仍待实现。
